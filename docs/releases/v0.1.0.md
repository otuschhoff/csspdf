# csspdf v0.1.0

Release date: 2026-09-09.

This is the first public pre-v1 release of csspdf. The supported Go API is the
`github.com/otuschhoff/csspdf/docflowpdf` package. The release is licensed
under the MIT License.

## Highlights

- Render HTML templates, CSS, flow definitions, JSON or Go payloads, reusable
  PDF templates, images, and registered fonts through a reusable library API.
- Compose legacy or ordered CSS/HTML layers with deterministic precedence and
  shared flow inference.
- Paginate tables and text, repeat table headers, apply running footers, and
  render reusable templates with explicit or flow-relative placement.
- Produce deterministic output with a fixed clock and atomically replace file
  destinations after a complete successful render.
- Report structured diagnostic codes and stages while preserving wrapped
  causes for `errors.Is` and `errors.As`.
- Enforce rendering, source, decompression, and output budgets, including
  context cancellation at public rendering boundaries.
- Resolve untrusted file-backed assets through an `os.Root`-confined resolver;
  trusted unrestricted filesystem access requires an explicit resolver.

## Compatibility and Migration

- Go 1.26.6 is the minimum supported toolchain. CI covers Go 1.26.6 and Go
  1.27.x on Linux, macOS, and Windows amd64.
- Rendering is strict by default. Missing or invalid required content returns
  an error instead of silently producing an incomplete PDF.
- `RenderInput.AllowPartialRender` and `WithLegacyPartialRendering` temporarily
  restore warning-and-continue behavior for recoverable failures. They are
  deprecated, retained through v0.2.x, and scheduled for removal in v0.3.0.
- `RenderInput.WarningWriter` and `WithWarningWriter` are deprecated in favor
  of `RenderInput.Logger` and `WithLogger`. They are retained through v0.2.x
  and scheduled for removal in v0.3.0.
- Dynamic JSON numbers use `json.Number` to preserve integer precision. Code
  that assumed every decoded number was `float64` must handle `json.Number`.
- `i18n.New` no longer searches ambient current or parent directories. Supply
  an `I18nSource` or configure `AssetBaseDir` for profile-owned translations.
- `RenderToFile` renders completely before atomically replacing its target;
  failed renders preserve an existing destination.

See `docs/phase1-migration.md` and `docs/api-compatibility.md` for the complete
contracts and migration examples.

## Security

The release includes confined asset resolution, immutable input normalization,
resource limits, bounded PDF inspection, context-aware rendering, and pinned
reachable-code vulnerability scanning. The release-candidate scan reports no
known reachable vulnerabilities. This is an engineering security posture, not
a PDF conformance certification or legal assessment.

## Known Risks

- The API is pre-v1; future minor releases may contain documented compatibility
  changes required for correctness or security.
- Legacy partial rendering can intentionally produce incomplete documents and
  should be used only as a temporary migration path.
- Filesystem replacement follows host `os.Rename` semantics and does not promise
  durability across power loss or kernel failure.

There are no open P1 or P2 findings in the current code-quality review.

## Validation

The release candidate passes the full quality and package-coverage gates under
Go 1.26.6 and Go 1.27.1, all-scope maintainability checks, root and nested race
tests, and the pinned reachable-code vulnerability scan.
